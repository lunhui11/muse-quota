# 账号池与网盘任务交接

已实现目录绑定、每日文本资料同步和内置 Muse 网页执行器。执行器逐步发送任务、读取回复、保存完整进度；达到额度阈值后关闭当前账号会话，上传并校验交接文件，再用下一账号读取文件续做。注册、Muse 登录和 Google 授权仍需使用你自己的账号完成。

## 首次使用

1. 手动注册、登录 Muse 账号，在本项目中添加账号并检测额度。
2. 在每个账号的「编辑」中填写对应 Google Drive 目录链接或 ID。内置执行器直接下载并校验目录中的资料后交给 Muse，因此不依赖 Muse 的网盘索引延迟。若要在 Muse 官网直接浏览网盘，仍需逐个账号手动完成官方网盘连接。
3. 为上传程序配置 Google 授权。所有目录都必须允许同一个上传身份写入；不同 Google 账号的目录可以共享给该身份。目录共享不等于 Muse 已经连接目录，后者需在每个 Muse 账号里分别完成。
4. 在「每日同步资料」中保存文本资料。每天北京时间 08:00 后，运行中的服务会将这些资料写入所有已启用且已绑定目录的账号；服务当天晚启动会补执行一次。也可以点「立即同步」。相同资料更新同一文件，不每日产生重复文件。

若还要把你手动放入每个绑定目录的文件作为当天任务资料，在 `.env` 设置 `DRIVE_IMPORT_ENABLED=1` 并重启。服务每天北京时间 `DAILY_SYNC_HOUR` 后读取该目录的 `.txt`、`.md`、`.json` 文件，生成可校验的当日快照；任务分配前若当天尚未读取，也会先读取一次。「立即同步」可强制刷新当日快照。最多读取 20 个文件，单文件不超过 20 KiB、总内容不超过 50000 字符，必须是 UTF-8。服务自动生成的交接文件不会当作输入。读取失败会显示错误并阻止该次任务分配，避免沿用昨天的资料。Muse 官网中的 Google Drive 连接仍需每个账号自行完成官方授权；这里的读取和交接使用服务单独的 Google API 授权。
5. 在「添加任务」中输入任务要求，点击「启动自动执行」。默认每 5 秒检查一次可领取任务；同一时间只执行一个任务。未配置网盘或没有可用账号时显示等待原因，不能发送聊天。
6. 点击「暂停自动执行」时停止领取，等待当前步骤结束后保存进度。页面显示「未启动」后可关闭服务。重启服务后默认不自动发送，需要再次点击「启动自动执行」。

Google 授权优先使用 `.env` 中的 `DRIVE_OAUTH_CLIENT_ID`、`DRIVE_OAUTH_CLIENT_SECRET`、`DRIVE_OAUTH_REFRESH_TOKEN`。也支持 `DRIVE_CREDENTIALS_FILE` 或已有 `GOOGLE_APPLICATION_CREDENTIALS`，通过官方 google-auth-library 使用这些凭据。文件存在不等于授权可用；绑定目录和上传时会检查实际权限。凭据文件放在被忽略的 data/ 内或仓库外，不要提交到 Git，也不要通过聊天发送令牌。

用户 OAuth 配置需要在 Google Cloud 项目启用 Drive API、建立 OAuth 客户端、用户同意 `https://www.googleapis.com/auth/drive` 范围并取得离线 refresh token。Google OAuth 测试模式的用户授权可能到期，长期使用应按 Google 的应用发布要求配置。可使用已有用户授权凭据文件。服务账号只有在目标目录和 Google 存储规则允许写入时才能使用，不应假定其有个人网盘存储空间。

默认额度阈值为 90%，仍由 `PAUSE_AT_PERCENT` 控制。`DAILY_SYNC_HOUR` 设置每日同步小时（北京时间 0–23）。网页每 5 秒读状态，调度器每 15 秒运行。执行程序必须在步骤之间上报最新额度，不能只依赖默认 30 分钟的外部探针。

## 内置执行器如何工作

无需单独部署 MCP 或 muse2api。server.mjs 内置执行器使用 Playwright 打开 `data/profiles/<账号ID>` 中的独立会话，使用与额度探针相同的账号和固定代理。额度读取在同一浏览器上下文的单独标签页进行，不会导航掉聊天页面。执行过程中禁止同账号的外部检测、登录或编辑操作。

领取成功后，执行器通过 Google Drive API 下载当前账号的交接文件和引用资料，校验 SHA-256、任务归属、版本及内容。每一步把原始目标、资料、完整摘要、续做指令和成果文本放入新消息；让 Muse 只做一个有限步骤并返回带本步骤标识的进度 JSON。回复格式有误时不会另发“修复回复”消息，而是等待人工检查。新账号收到的是保存后的快照，不是前一账号的隐式聊天历史。

每个步骤开始前重新读取额度；达到 `PAUSE_AT_PERCENT` 或收到暂停请求时不再发送。等待当前回复稳定并确认停止生成，保存摘要与文本成果，关闭上下文，再进行网盘交接。新版本下一次轮询会自动领取。已保存的成果按文件名保留，后续步骤返回同名文件会替换全文。最终结果上传校验成功后，面板显示「已完成」，可展开查看文本成果或打开网盘文件。

在发送前写入磁盘日志，每次 Enter 只尝试一次；回复收到后先记录原文，再验证并保存快照。日志保存在 `data/executor/`，与 data/ 一起备份，不上传 GitHub。服务重启后：已经保存完整快照的步骤可恢复交接；可能已发送但没有确认快照的步骤进入 `needs_attention`，禁止自动重发、取消或分配这个账号给其他任务。

暂停原因包括登录失效、网盘文件变更、输入框中已有草稿、Muse 正在处理其他工作、出现人工确认窗口、超时、回复格式错误、磁盘失败及步骤上限。面板「检查并恢复」会显示最近回复和已有快照；先到原账号 Muse 确认工作停止，再修正摘要、续做指令和成果，勾选停工确认后保存。若实际已经完成，可勾选完成并上传最终结果。关闭浏览器本身不代表云端任务停止，不能省略人工确认。

执行器配置：

| 变量 | 默认 | 含义 |
|---|---|---|
| EXECUTOR_HEADLESS | 1 | 0 时显示执行浏览器，需要图形环境 |
| EXECUTOR_TIMEOUT_SECONDS | 300 | 单次回复等待上限，允许 5–1800 秒 |
| EXECUTOR_MAX_STEPS | 20 | 每次领取的步骤上限，允许 1–200；到达后保存进度等待人工检查 |

当前执行器适合能够用文本和文本文件表达进度的任务。成果上限与下方协议一致，合并后的任务输入最多 240000 字符。不会自动复制另一个 Muse 账号的云端虚拟机、下载二进制附件、转移官方连接器授权或保证外部发布操作仅执行一次。Muse 网页结构、生成完成信号或协议遵循发生变化时，需要真实账号联调修正，不能仅凭模拟测试宣称兼容当前现网。

## 外部执行程序协议

仍保留原有 API，供以后替换为自己的任务执行程序。内置执行器和外部执行程序不得同时处理同一个任务；重复领取返回 409。


所有请求在本机 API 上进行，JSON 请求体，无访问密钥。账号池接口请求体最多 256 KiB。

`GET /api/pool` 返回目录、资料、任务和交接状态。执行程序轮询属于自己账号的任务。状态 `ready` 表示交接文件已上传并下载校验，等待领取；它不表示任务已经开始。

领取：`POST /api/pool/tasks/<任务ID>/claim`

```json
{"account_id":"账号ID","revision":1}
```

200 后执行程序取得当前版本的执行权。响应包含 `bundle`（任务要求、已保存进度、成果文本和资料文件 ID）和 `file`（本账号网盘交接文件 ID、链接、SHA-256）。执行程序用对应账号打开 Muse，让 Muse 读取已连接目录中的该交接文件，并按 `checkpoint.next_steps` 继续。必须核对 Muse 确实读取了最新文件；网盘上传成功不等于 Muse 已索引成功。重复领取或旧版本请求返回 409，不应继续执行。

执行程序每完成一个可暂停的步骤，应读取当前额度并发送：`POST /api/pool/tasks/<任务ID>/quota`

```json
{"account_id":"账号ID","revision":1,"weekly_used_pct":92}
```

达到阈值后状态变为 `pause_requested`。过期或未知额度也会请求暂停。此时执行程序停止提交新步骤，等待当前步骤稳定结束，关闭使用该账号的浏览器上下文，然后提交进度：

`POST /api/pool/tasks/<任务ID>/checkpoint`

```json
{
  "account_id":"账号ID",
  "revision":1,
  "paused":true,
  "summary":"第一章已完成，尚未发布。",
  "next_steps":"读取 chapter-1.md，继续第二章；不要重新执行第一章。",
  "artifacts":[{"name":"chapter-1.md","content":"已完成的正文"}]
}
```

摘要和续做指令各最多 10000 字符；成果最多 10 个文本文件，每个内容最多 20000 字符。每次提交的是完整恢复快照，应包含续做所需的全部成果。二进制附件、聊天历史全文和账号 Cookie 不会自动导出；需要任务程序显式处理。`paused:true` 必须对应真实停工，不能把仍在执行的账号标记为已暂停。

账号池先保存本地快照，并将暂停进度单独上传、校验到源账号目录；即使没有备用账号也会完成这份备份。源目录备份失败显示 `checkpoint_upload_failed`，修复后重试，备份成功前不切号。然后按账号顺序选择下一可用账号；向源账号目录和目标账号目录写入同一个交接包，下载核对内容后，才把归属改到下一账号并递增 revision。同步资料失败、任何一份交接文件上传或校验失败时，归属不变，原账号保持暂停，状态显示 `upload_failed`。修复权限或网络后点击重试，或等待调度器重试。没有可用账号时显示 `waiting_account`，保留本地进度和源网盘备份，不重放任务。若没有其他可用账号，但原账号的额度重新检测后恢复到阈值以下，也可为该账号生成新版本并续做。

后续执行程序领取新版本，读取交接包，按续做指令工作。旧账号或旧 revision 的额度/进度上报返回 409。任务产生的发布、发送、付款等外部副作用，应由执行程序记录操作 ID 和完成状态；账号池不能独立保证这些业务操作仅执行一次。

完成时向同一 checkpoint 接口发送 `completed:true`、summary 和最终 artifacts；无需 next_steps。最终结果上传到当前账号目录，验证成功后才显示 `completed`；失败显示 `completion_upload_failed` 并保留本地结果等待重试。

服务重启后，曾经 `running` 的任务变为 `pause_requested`，不会自动重复派发。原执行程序确认停工并提交进度后，才能恢复交接。正在执行或等待暂停的账号不启动独立额度探针，避免争用持久浏览器目录；执行程序负责从自己的会话上报额度。

## API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | /api/pool | 读取完整账号池状态 |
| POST | /api/pool/accounts/ID/folder | 绑定目录，JSON：folder_id |
| POST | /api/pool/documents | 保存文本资料，JSON：title、content |
| POST | /api/pool/sync | 立即同步资料到所有已启用的目录 |
| POST | /api/pool/tasks | 添加任务，JSON：prompt、可选 request_id；同键同内容返回原任务，同键不同内容 409 |
| GET | /api/pool/tasks/ID | 查询单个任务 |
| POST | /api/pool/tick | 立即运行一次调度/重试 |
| POST | /api/pool/tasks/ID/claim | 领取任务 |
| POST | /api/pool/tasks/ID/quota | 上报当前账号额度 |
| POST | /api/pool/tasks/ID/checkpoint | 暂停交接或完成任务 |
| POST | /api/pool/tasks/ID/cancel | 取消尚未执行或已安全暂停的任务 |
| POST | /api/pool/tasks/ID/resume | 人工确认停止后提交进度；字段同 checkpoint，paused 必须为 true |
| GET | /api/executor | 内置执行器状态 |
| POST | /api/executor/start | 开启自动领取和执行 |
| POST | /api/executor/pause | 停止领取，当前步骤结束后保存进度 |
| GET | /api/executor/tasks/ID | 当前版本的最近回复与本地快照 |

## 验证范围

`npm test` 执行原有浏览器测试、test-pool.mjs、test-pool-regressions.mjs 和 test-executor.mjs。账号池测试覆盖三个账号交接、每日同步、上传失败不切号、完整进度与成果复制、重复领取、旧版本更新拒绝、重启恢复和结果上传。新增 9 项回归覆盖磁盘保存失败、源网盘备份、额度恢复、新目录补同步、完成状态保护、凭据回退及并发领取。新增执行器测试使用真实临时 Chromium、拦截的 Muse 页面和模拟 Google HTTP，验证完整的 1 号发送 → 达到阈值 → 网盘交接 → 2 号下载续做 → 成果上传，并覆盖回复校验、重启不重发、暂停、草稿保护、异常恢复和手机布局。全部网络响应为测试夹具；不代表真实 Drive OAuth、目录权限或当前 Muse 网页已经通过验收。

真实接入应使用一个低风险测试任务：1 号完成一步，上报达到阈值，确认暂停并上传；核对两个目录中的交接文件一致；2 号领取后读取文件并继续下一步。完成该验证前，不应把状态 ready 宣称为真实任务执行成功。

## 错误恢复补充

交接和完成状态必须写入磁盘成功后才对执行程序生效。磁盘保存失败会回退内存到最后一次成功保存的状态；修复目录权限后重试，旧的任务归属和版本仍受校验。新增或变更网盘目录会触发当天已有资料的补同步。已完成的任务不能取消，避免覆盖最终状态。

## 微信接入状态

目前采用用户新提供的 [wechat-muse-bridge](https://github.com/huangzuomin/wechat-muse-bridge/blob/main/README.zh-CN.md) 作为复用候选。已读取 README、收发代码和安装脚本，在临时隔离目录安装依赖并运行上游 57 项测试，全部通过；尚未登录微信或生成真实二维码。这个项目需要部署设备已有 Muse Gadget CLI/service/socket，并连接单个 Muse Side Chat。入站会自动转发，出站需要 Muse 主动通过设备工具调用 wechat-muse-send。

已提供 [交给 Muse 执行的两阶段提示词](muse-wechat-prompt.md)：先接通微信和固定 Muse，再把明确的微信任务接到现有账号池，保留额度和 Drive 交接的职责。代码研究发现默认回复寻址会受被过滤消息影响，发送者切换缺少 context_token 时可能复用旧 token；提示词要求部署前小范围修复与回归。上游测试通过不等于实际微信/Muse 验收完成。此前用户提供的 penghuitiyu/wechat-ilink-bridge 不可访问，此次未再尝试部署该仓库。

## 微信适配框架更新

本地已实现 integrations/wechat。微信文本在默认任务模式直接进入本账号池，无需 Gadget；可选聊天模式继续复用 Gadget。服务端 request_id 是持久幂等键，可恢复创建响应丢失和消息重放；单任务 GET 和 capabilities 用于适配层版本预检。微信任务归属、收件箱与发件箱在私有 SQLite 中持久化，结果通知按任务所有者回传，不依赖最新任意发言者。详见 [部署说明](../integrations/wechat/README.md) 和 [Muse 最终接手任务](MUSE_HANDOFF.md)。
